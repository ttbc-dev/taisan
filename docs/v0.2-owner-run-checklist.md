# v0.2 owner-run acceptance checklist

This checklist is executed by the owner (or an operator the owner
designates) on a real installation. It exercises the public reference
path and a configuration-only generic adapter replacement. It is not
executed by the implementing agent: preparing this checklist creates no
live Issues, enables no normal-installation automation, and launches no
real Workers.

Record every result in the
[owner-run evidence template](v0.2-evidence-template.md). Label each row
as **automated fixture/contract evidence** or **owner-run live evidence**. An owner-run live row is never marked passed from a fixture
or contract result.

## Roles and record locations

| Role | Responsibility |
| --- | --- |
| `owner` | Authorizes the run, selects the two Issues and repositories, approves the evidence. |
| `operator` | Runs the commands, captures times and outputs, fills the evidence template. May be the owner. |
| `agent` | Prepares instructions only; creates no live Issue, enables no automation, launches no Worker, and does not authorize. |

Record locations: `CFG` = sanitized `config.toml` **and** the
sanitized installation record (`store.config.json` beside `--db`, or
the `--config` path) copied into the evidence record; `STATE` = the
installation state directory (`store.db`, `bodies/`, `workspaces/`);
`JSON` = the retained JSON
envelopes for each command; `RUNS` = `taisan intake-runs` and
`taisan intake-detail` output; `HOST` = the real Issue, run, proposal,
command, and Work references on the source host; `TEMPLATE` = the
owner-run evidence record.

## Preconditions

| # | Who | Check | Expected |
| --- | --- | --- | --- |
| 0.1 | owner | Two distinct real eligible Issues exist in the allowlisted repository: **Issue A** for existing/manual Work and **Issue B** for scheduled intake. Optionally **Issue C** for a second scheduled admission. | Two (or three) open, eligible, non-overlapping Issues with stable identities. |
| 0.2 | operator | The installation is a dedicated reference repository; credentials are scoped to it and supplied as references. | No credential value appears in `CFG`, `JSON`, logs, or evidence. |
| 0.3 | operator | `taisan check` passes. `taisan check --probe` is **not** part of the gate: no adapter probe backend is wired yet, so its stage 8 fails closed with `capability.unknown`. | Ordered per-stage pass, or the failing stage is recorded and fixed before proceeding. |
| 0.4 | operator | Intake starts with `enabled = false`; the one `[intake.selector]` binding is `public-issue-selector`. | Clean install is not already running scheduled intake. |
| 0.5 | owner | The live authorization (scope, Issues, profile, retention, expiration) is recorded before the first live command. | Timestamped authorization reference precedes 1.1. |

## Scenarios

### L-1 — existing execution on Issue A

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 1.1 | operator | Submit Work for **Issue A** manually through the CLI or the installed skill. | `accepted`; one Work and one queued Execution; no second queue. | `JSON`, `HOST` |
| 1.2 | operator | Start `taisan run` with intake still disabled. | The existing Work advances through the normal execution lifecycle; no scheduled intake run appears. | `RUNS`, `HOST` |
| 1.3 | operator | Inspect `work-detail`, `attention`, and `capacity` at start and at terminal/human-gate state. | Recorded state, evidence, and any Attention are consistent; no ghost run or false success. | `JSON` |

### L-2 — scheduled intake admits Issue B (and optionally C)

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 2.1 | operator | Enable intake (`enabled = true`) while `taisan run` is live; wait for the 60-second settings tick. | Startup/re-enable transition makes intake immediately due once; no duplicate launch. | `RUNS` |
| 2.2 | operator | Let the scheduled run admit **Issue B** (and optionally **Issue C**) through the normal submit path. | At most one Work per eligible source; candidates are `accepted` or `replayed`; order is preserved. | `RUNS`, `JSON`, `HOST` |
| 2.3 | operator | Wait for the next 30-minute grid point. | One new scheduled run at the interval, not a catch-up burst; no run while one is already active. | `RUNS` |
| 2.4 | operator | Confirm the scheduled Work uses the same existing execution and Outcome contracts as Issue A. | Queue, dispatch, evidence, and terminal state follow the unchanged lifecycle. | `HOST` |

### L-3 — restart

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 3.1 | operator | Stop `taisan run` with SIGINT/SIGTERM at a phase boundary, preferably while intake is imminent or an execution is active. | The process exits cleanly; no OS timer remains; durable run/lease records remain. | `RUNS` |
| 3.2 | operator | Restart `taisan run`. | A live/uncertain intake run is reconciled by its durable owner evidence; with no active run and intake enabled the startup rule makes intake due; no duplicate Work is admitted. | `RUNS`, `HOST` |
| 3.3 | operator | Inspect `intake-runs`, `work-list`, and `capacity`. | Recorded identities and states survive restart; missed periods collapse to the next future grid point. | `RUNS`, `JSON` |

### L-4 — duplicate presentation

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 4.1 | operator | Run one-shot `taisan intake` twice against a source already admitted (or let the adapter present the same issue/proposal again). | The second presentation replays the recorded decision or is refused as source overlap; exactly one Work exists for that source. | `RUNS`, `JSON`, `HOST` |
| 4.2 | operator | Verify the same-proposal-key and overlapping-source cases separately. | Same key returns the saved decision; an unfinished source claim yields no second Work; a terminal release permits a new explicit submission only. | `JSON`, `HOST` |

### L-5 — full queue

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 5.1 | operator | Fill the pending queue to `pending_queue_limit = 10` with eligible queued Work. | The next manual submit is `capacity_exhausted`; no partial Work, Execution, claim, or usage row commits. | `JSON`, `capacity` |
| 5.2 | operator | Let a scheduled run reach the full queue. | The candidate is `capacity_deferred` with no decision link; it is not a saved rejection; no adapter relaunch burst. | `RUNS` |
| 5.3 | operator | Drain one position, then retry the same manual submission or the next scheduled run. | Admission succeeds when a position is free; existing executing Work is never cancelled by the full queue. | `RUNS`, `JSON` |

### L-6 — selector outage

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 6.1 | operator | Make the selector unavailable for one invocation: remove source access, force a timeout, or use a failing adapter path. | The run records a bounded typed failure (`adapter_source_unavailable`, `adapter_authentication_failed`, `adapter_deadline_exceeded`, or the matching `exchange_*` code for a launch or transport failure); zero candidates submit. | `RUNS` |
| 6.2 | operator | While the selector is unavailable, submit manually and observe existing Work. | Manual `submit` and existing execution continue; the failed intake does not stop or fail them. | `JSON`, `HOST` |
| 6.3 | operator | Restore the selector and wait for the next due time. | The next run is attempted normally; no blind retry storm or duplicate admission. | `RUNS` |

### L-7 — configuration reload

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 7.1 | operator | Disable intake, then re-enable it, with `taisan run` live. | Disable cancels the pending due; re-enable is immediately due on the settings tick; an in-flight run completes under its captured settings. | `RUNS` |
| 7.2 | operator | Change `interval_minutes` from 30 to another positive value. | `next_due` resets to the reload tick plus the new interval; no immediate catch-up run. | `RUNS`, `CFG` |
| 7.3 | operator | Change only `[intake.selector].adapter` and `argv` to the generic conforming adapter. | The new binding is used at the next settings tick; `next_due` is preserved; accepted Work keeps its original binding. | `RUNS`, `CFG` |
| 7.4 | operator | Introduce one invalid intake value, then fix it. | Only that settings tick is suppressed with a bounded error; the last valid settings continue; the next tick recovers; existing Work is not stopped. | `RUNS`, `CFG` |

### L-8 — history inspection and close-out

| # | Who | Action | Expected result | Record |
| --- | --- | --- | --- | --- |
| 8.1 | operator | Run `intake-runs`, `intake-detail` for each run, `work-list`, `work-detail`, `capacity`, and `command-result` for replayed keys. | Run/candidate order, states, settings revision, bounded reasons, and command/Work links are present and consistent. | `RUNS`, `JSON`, `HOST` |
| 8.2 | owner | Confirm no merge, deploy, auto-merge, or dependency on a private integration occurred. | Scenario PRs remain open; only the public reference path and the separately validated generic adapter were used. | `HOST`, `TEMPLATE` |
| 8.3 | owner | Review every row, deviations, unexercised scenarios, and redaction. | Live rows are labeled owner-run live; fixture rows are labeled automated fixture/contract; every gap is marked `unexercised` with a reason. | `TEMPLATE` |

## Expected results summary

| Scenario | Pass condition |
| --- | --- |
| Existing execution (L-1) | Issue A's Work completes or reaches the expected human gate under the unchanged lifecycle. |
| Scheduled intake (L-2) | Issue B (and C) are admitted at the internal interval, one Work per source, no OS timer. |
| Restart (L-3) | Durable identities and states survive; no duplicate Work; no catch-up burst. |
| Duplicate presentation (L-4) | Replay or overlap refusal; exactly one Work per source. |
| Full queue (L-5) | `capacity_exhausted` / `capacity_deferred` with no partial rows; existing Work unaffected. |
| Outage (L-6) | Bounded typed failure with zero candidates; manual submit and existing Work continue. |
| Configuration reload (L-7) | Enable/disable, interval, and adapter changes take effect at the settings tick; accepted Work is unchanged. |
| History (L-8) | Every run, proposal, command, and Work reference resolves and is retained. |

## Failure handling

- A failing precondition stops the run; record it and do not proceed to
  a live row.
- A scenario may be marked `unexercised` with a reason; it is never
  marked passed by implication.
- A fixture/contract result cited after a live row is supplemental only;
  it does not convert an unexercised live row into a pass.
- Any credential appearing in a retained surface is an incident: stop,
  redact the record, and rotate the credential before continuing.
