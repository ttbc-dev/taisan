## Residual risks / open items

- No production scheduler persists a `recovery_intents` row inside a
  deciding transaction yet (the U5.6 producer). LP-25/LP-27 therefore
  exercise the automatic consumer with fixtures seeding the
  crash-after-scheduling state. The producing side is U5.6 scope
  (#96) and was not built here.
- Suppression is durably recorded via the existing deferral
  mechanism (`RecordDeferral`, the same upsert path the dispatch
  `recovery_conflict` uses): the intent stays `Pending`; the
  Execution carries `reason: equivalent_failure_suppressed` with a
  diagnostic naming the streak and the policy limit; the phase-6
  scan also surfaces the hold. No schema change was made.
- LP-27's unresolved-effect hold relies on the existing
  `RepairPrerequisite::EffectResolution` gate. The only new guard in
  this slice is the LP-26 suppression branch in `fire_due_intent`
  (equivalent-failure streak at the policy limit => suppressed, never
  consumed), placed immediately before the requeue decision.
- Fixture Work IDs/identities are deterministic only within a test;
  nothing here claims anything about live evidence classes.
