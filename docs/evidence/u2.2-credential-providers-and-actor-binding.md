## Configuration under test

`CredentialRef` is an opaque `identity.rs` id type: Core stores the
`kind:name` reference string only, and `workloop-core::credential::
CredentialProvider::parse_str` decomposes it into the slot (env name,
absolute path, argv) — shape only, never a resolved value.
`workloop-config` delegates `credential_ref` validation to that parser,
so the loader and the adapter boundary share one grammar
(`docs/installation-config.md`).

Resolution lives in `workloop-github::credential` at the adapter
boundary: `resolve_credential` maps `env:`/`file:`/`command:` through
the `CredentialProviders` trait (process environment, filesystem,
child processes; the fixture seats an in-memory environment), and
`bind_credential` authenticates the resolved value and compares the
result to the actor the intent binding authorized. `file:` demands a
regular file owned by the current user with owner-only permissions —
`mode & 0o077 != 0` is refused before any byte is read; on non-POSIX
platforms the provider fails closed. `command:` runs argv directly (no
shell); the secret travels on stdout, never on argv or in exported
environment. `ResolvedCredential` redacts `Debug`/`Display`; the value
leaves only through `expose()` inside adapter authentication.

`FixtureGithub::attempt` resolves and binds the persisted Work
binding's credential slot for the intent's role before every write;
failures leave the intent `Pending` and are reported as
`OutboxReport::credential_blocked` entries carrying the typed
`credential.*` code — the intent's saved `actor` is never rewritten.

## Non-claims

- No live credential was resolved: the `env:` seats are in-memory
  fixture slots; the only real I/O exercised is the `file:`/`command:`
  providers against test temp files and `/bin/cat`, `/usr/bin/printenv`.
- No live host API, Worker runtime, or E2E scenario was contacted;
  `CredentialBook::authenticate` stands in for the host's credential
  authentication.
- Denial and expiry classes are exercised through the fixture's
  reported outcomes; mapping a real host's authentication errors into
  `credential.expired`/`credential.unresolvable` remains a live-adapter
  concern, deferred with the live evidence gate.
