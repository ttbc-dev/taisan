## Configuration under test

- Loop settings (defaults from the [execution loop](../execution-loop.md)
  owner decisions, overridable via the installation `loop` section):
  `interval_seconds = 30`, `tick_deadline_seconds = 120`,
  `source_refresh_timeout_seconds = 30`.
- Per-tick bounds enforced by the driver: host outbox ≤ 8 attempts/tick,
  recovery scheduling ≤ 16 intents/tick.
- Retention sweep defaults (from the [retention policy](../retention-policy.md)
  configuration table): enabled, `interval_seconds = 3600`,
  `max_bodies = 256`, `max_bytes = 1073741824`, `delete_error_limit = 3`.
- Installation: fixture adapter, default capacity from the generated
  config (tests that need two slots rewrite `capacity` explicitly),
  no `worker_argv` in driver tests that pass `supervisor: None`
  (supervisor behavior is covered by the `workloop-exec` contract suite).
- Store: fresh v1 SQLite store per test (schema includes `run_lease`,
  `recovery_intents`, `body_catalog`, `body_pins`; a previous-release v1
  store without them is upgraded in place at open, with its boolean
  pins reconstructed as ledger rows —
  `contract_commands::a_previous_release_v1_store_is_upgraded_in_place`,
  `contract_retention::a_pre_ledger_pin_survives_the_upgrade_and_beats_an_unrelated_clear`).
