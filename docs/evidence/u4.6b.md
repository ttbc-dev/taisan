## What the rerun exercises

`run_recorded_suite(tag, bin)` executes the identical ten-case scenario
table (`scenarios()`) through the same public Command/admission helpers,
the supervisor passes, and the durable `SqliteStore` — twice. The only
variable between the two calls is `bin`, the configured `worker_argv`
the supervisor binds: the reference fixture worker
(`workloop-fixture-worker`) in run A and the independent deterministic
contract Worker (`workloop-contract-worker`) in run B. Each covered case
retains a U4.6-format record (`schema_version`, `tested_revision`,
`base_revision`, `claim_class`, `configuration_identity`,
`command_scenario`, `result`, `evidence_refs`) plus an adapter-neutral
`CaseSignature` — execution state/waiting/terminal/invocations-used,
invocation state/role/writer-identity presence, host-action intent
statuses, and the process-control port's spawn count. Records may
differ only in adapter identity; signatures must be identical. The
named run writes both runs' twenty records to
`target/u4.6b-records.json` whenever the checkout yields a faithful
revision stamp (as in the verification commands below), so the
summaries in this document can be re-derived from the run itself
rather than transcribed by hand.
Revision stamping is fail-closed and gates retention: a record is
built only when the run has a faithful stamp — the tracked tree is
pristine (a cited commit only describes the exercised tree when no
tracked file differs from it) and both fields validate as full 40-hex
commit ids. Where a stamp exists, a CI run cites the workflow event's
real head/base commits (its depth-1 checkout keeps no base history to
resolve, but the payload records the real commits), a normal checkout
stamps `HEAD` and its merge-base, and a checkout with no resolvable
base ref cites the deepest commit it retains. A checkout that cannot
produce that stamp — uncommitted tracked changes, a non-git source
tree, a `git` failure — runs the identical suite and every
record-independent assertion, builds no records, and retains none:
no record can ever carry a placeholder such as `unknown`, and the
prescribed `cargo test --workspace` stays runnable mid-edit. The
exemplars below are the records the run stamped at the tested
revision above.

The named run
`u46b_identical_suite_under_either_adapter_has_per_case_outcome_equality`
executes both runs and asserts, per case: identical case id, identical
result, identical missing-capability set, identical signature, and
record equality field by field — `schema_version`, `tested_revision`,
`base_revision`, `claim_class`, `command_scenario`, `result`, and
`evidence_refs` equal across the pair, and the whole
`configuration_identity` equal after projecting out only the
bound-worker fields (`adapter_id`, `adapter_version`,
`runtime_version`, `capability_digest`, `argv`; the request id and the
installation identity are kept and therefore compared) — "differ only
in adapter identity" as whole-record equality, not a spot check. Where
a case binds an adapter, the bound adapter ids are asserted different
and both members of the declared adapter set (non-vacuous), inside the
marked identity boundary. The named static check
`u46b_suite_source_has_no_adapter_name_branch` scans the suite's own
source (`include_str!` on `crates/workloop-exec/tests/worker_contract.rs`)
and asserts adapter-name literals appear only
inside the marked `adapter identity boundary` and never on a
conditional, comparison, or assertion line, and that the
identity-revealing identifiers — the binary getters
(`fixture_bin`/`contract_bin`), the boundary list
(`SUITE_ADAPTER_NAMES`), the bound construction (`make_bound`), the
binding fields (`adapter_id`, `adapter_version`, `runtime_version`,
`capability_digest`, `argv`), and the supervisor's `worker_argv` — appear
outside that boundary only on branch-free data lines: every identity
comparison lives in the boundary, so no case branches on which worker
is bound. The scan is lexical: it catches branches that mention an
identity token, while branches through renamed aliases remain outside
what a token scan can see.

Skipped is a result, not a substitution: a case whose required model
capabilities a real argv cannot declare (`spawn_unknown`,
`liveness_unknown`, `signal_survived`, `signal_audit`) is skipped
identically for both implementations, and the skip surface itself is
asserted equal.

## Configuration under test

The installation identity is the local test installation
(`host_instance = test-host`, `repository = local-repo`, adapter
`worker-contract`, contract version `1`). The Worker selection under
test is the configured `worker_argv`: the reference-fixture binary and
the independent deterministic contract Worker. Each selection reports
through the effect-free `describe` operation:

- adapter ID: `workloop-fixture-worker` or `workloop-contract-worker`;
- adapter version `1.0.0`; runtime version `fixture-1.0.0` /
  `contract-1.0.0`;
- capability digest `903619b2baf3427f681f7119da1644b2491a81a232948767360bcb8f88158f75`
  (reference) / `d2b06e35a835558300085fbde20d3ce6bf4fd9c2643714ecd1b72d8a02f74848`
  (contract Worker), covering the declared protocol/role/capability
  surface.

The first binding is stored on the durable `InvocationRequest`
(`adapter_binding`) and is immutable for the request's life. A case that
reconciles a recorded writer without dispatching a start (WC-START-01),
or one that never consumes its pending request (WC-REV-01), records an
empty `adapter_selection` — no adapter was bound for that request.
`argv` below is normalized to the binary basename plus the worker mode;
in the exercised tree the suite passes each binary's absolute target
path.
