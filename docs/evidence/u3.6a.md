## Evidence record format

The normative format is in
[repository-host-contract](../repository-host-contract.md#u36-evidence-record).
A record contains `schema_version`, `tested_revision`, `base_revision`,
`core_revision`, `adapter_revision`, `config_identity`
(`install_identity` — host instance, repository, adapter, contract
version — plus `config_digest`, the sha256 of the canonical
configuration projection), `command_or_scenario`,
`action_identities[]`, `observation_identities[]`,
`read_back_receipts[]`, `result`, and `claim_class`
(`fixture_contract` or `live_evidenced`). `authorization_reference` is
required iff `claim_class` is `live_evidenced` and is absent — never
null — on a `fixture_contract` record. A record missing any required
field is invalid; `workloop_github::evidence::validate_record_json` is
the field-presence check, applied to typed records and retained JSON
alike.

## Configuration under test

Each run binds the test installation (`host_instance = test-host`,
`repository = local-repo`, contract version `1`, publication actor
`push-agent`) to one adapter implementation — `fixture-github` (the
GitHub adapter; the GitHub-shaped fixture the U3 contract targets) or
`sparse-host` (the independent fixture implementation: a scoped event
journal with its own per-subject version tokens, no shared code with
`FixtureGithub`). The `config_digest` differs per adapter because the
adapter id is part of the digested projection.

`SparseHost::observe`/`read` serve `Complete` typed reads for the
subjects its remote journals (change-request head, branch head).
Subjects the sparse remote does not journal — including kinds its
`declared_capabilities` vocabulary carries (repository, check,
review), which the U3.1 suite exercises through the normalized port
via `emit`/`attempt` deliveries — answer `Partial`, and kinds outside
its declared set (issue, diff) answer `Partial` too: the host never
invents a revision.

## Acceptance criteria mapping

| Criterion | Where exercised | Result |
| --- | --- | --- |
| Record format captures tested revision, configuration, command/scenario, action identities, read-back receipts and result; distinguishes fixture vs live claims via `claim_class` | [repository-host-contract](../repository-host-contract.md#u36-evidence-record) defines the closed shape; `EvidenceRecord` serializes it | pass |
| Field-presence check asserts every retained record carries all required fields; `live_evidenced` additionally requires `authorization_reference`, whose absence invalidates | `evidence.rs` tests: a complete record validates; every `REQUIRED_FIELDS` removal is a violation; `live_evidenced` without the reference is invalid; the reference on `fixture_contract` is invalid; the retained set is validated in the suite run | pass |
| Stale-head observations never move the recorded current head backward; duplicate deliveries deduplicate to a single effect — for both fixture and GitHub adapter runs | `stale_head_never_rolls_back` and `duplicate_delivery_deduplicates` run unchanged on `FixtureGithub` and `SparseHost`; one retained record per scenario per adapter above | pass |
| Retain verification evidence with the tested revision, configuration, command/scenario and result; tested revision is the branch commit containing the slice tree | this record plus `record_revisions` fail-closed stamping — a checkout that cannot prove the commit retains no records; the retained JSON is written to `target/u3.6a-records.json` | pass |

## Non-claims

- No real GitHub API call was made; `FixtureGithub` is the GitHub
  adapter model and `SparseHost` an independent fixture — fixture
  passes are modeled-behavior evidence only. The real adapter (#17)
  produces `fixture_contract`-shaped records under the same format
  when it runs this suite; live claims remain separately authorized.
- `core_revision`/`adapter_revision` equal `tested_revision` for these
  in-repo fixtures — the fields stay semantically distinct for a
  separately-built adapter (e.g. an external adapter build).
- Write-path, reconciliation and consolidated records are the U3.6b–d
  slices; the authorized isolated live cases are U3.6e.
- `GitlabFixture` gained no typed reads in this slice — the issue
  scopes the read path to the fixture and GitHub adapter runs.
