Claims boundary: this is a **live** result. One real Work item was
submitted through the real CLI, dispatched by the real run loop,
executed by a real spawned Worker process against a real clone of the
isolated scenario repository, published to real GitHub (branch + pull
request), checked and reviewed by real GitHub Actions runs, judged and
fixed once — and then the run **halted into Attention**: the second
automatic fix admission hit the Work-wide `max_fix_invocations` bound
and the Execution paused with an operator-decision hold. All of this
went through the real `work::handle_command`/`handle_observation`
pipelines and the SQLite durable store. Fixture adapters produced **no**
evidence in this run: the installation declared `adapter: s1-bridge`,
which the run loop treats as an out-of-process adapter (the in-process
fixture drain is skipped).

Non-convergence was engineered, not accidental: `worker-shim-nc.sh`
emits a `greet()` variant that passes the repository verification on
every round while still carrying the seeded review-visible gaps (no
docstring, no explicit `None` literal), so the real review flags every
published head and the loop can never converge on its own. The bound
that halts it is installation policy (`max_fix_invocations: 1`),
stamped into the Work's immutable policy at acceptance.

Honest scope limits, stated once: (a) the host side is the
**scenario bridge**, not the production GitHub adapter (U3.x remains
open) — it performs real effects through `git`/`gh` and reports real
read-backs; (b) the Worker is a **deterministic scenario shim**, not a
coding-agent runtime (U4.2 remains open) — its rounds are scripted
variants that cannot satisfy the review contract; (c) the
"invariant-check" leg is an **Assessment fact** verified on the real
diff (bounded writable paths, no-force-push ancestry), not a separate
invariant-check Invocation; (d) `push_ref.produced` is the artifact
payload digest per the Core contract, while `observed`/`relation`
record the real remote ref value and its containment of the produced
content; (e) the reviewer identity is `github-actions[bot]` — real
GitHub-authenticated pull reviews bound to commit SHAs and produced by
a real CI job inspecting the real checked-out diff, not a human review
and not a fixture.

## Scenario mechanics (why the run cannot converge)

1. `inv-1` (Coding) produces H1 `6c24870` — `verify` passes, the real
   review flags `missing-docstring` + `unguarded-none`; `e-2` pauses for
   human disposition (Attention #1).
2. `jdg-1`/`cmd-5` release the gate; `inv-2` (Fix) consumes the single
   fix-attempt slot and produces H2 `397deda` — republished through the
   same real push path. The review on H2 flags the identical two
   findings; `e-2` pauses again (Attention #2).
3. `jdg-2`/`cmd-7` release the gate a second time; the requeued
   Execution's next admission is a Fix — but
   `work_usage.fix_invocations_used (1) >= policy.max_fix_invocations
   (1)`, so admission pauses instead of requesting `inv-3`. No worker
   spawn, no counter increment, no intent: the bound held (Attention
   #3 — the halt this unit exists to observe).
4. `cmd-8` acknowledges the halt Attention: the listing empties, the
   pause, holds, and budget ledger are all unchanged (A-2).
