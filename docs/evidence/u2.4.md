# U2.4 verification evidence — setup and permission preflight

Slice: U2.4 (`init` scaffolds the install config carrying allowlist,
credential references, and observed identities; `check` runs the
ordered offline fail-closed preflight — config parse → identity tuples
→ credential-reference presence → paths → worker runtime → isolation
primitives → store → `--probe`-only capability reads — stopping at the
first failing stage with a stage-scoped diagnostic; `--probe` is
opt-in, read-only, and never a lasting grant) in
`crates/workloop-config/src/preflight.rs`, `crates/workloop-config/src/profile.rs`
(`identity_evidence` schema), `crates/workloop-core/src/ports.rs`
(read-only `ProbePort`), and `crates/workloop-cli/` (`taisan init`,
`taisan check [--probe]`).

Claims boundary: every result below is a **fixture/contract** result
produced by local tests. It supports contract claims about this
repository only. No live host, Worker, or E2E scenario was run; the CLI
`--probe` stage has no wired adapter backend in this runtime and fails
closed by design. Any live claim requires separately authorized live
evidence under the
[implementation start gate](../design-closure.md#implementation-start-gate).

## Configuration under test

- Profile schema: `config.toml`, `schema_version = 1`, loaded by the
  U2.1 validator; `init` renders it and round-trips it through the same
  loader before the atomic publish.
- One host (`h1`, `github`, endpoint `https://***.github.com`,
  `contract_version = 1`) with one `publication` repository
  (`0123456789`) and one `source` repository (`5566778899`).
- Roles: `publication` → actor `taisan-publisher` → `env:TAISAN_TEST_TOKEN`;
  `review` → actor `taisan-reviewer` → `file:<temp>/review.token`
  (created `0600`); one scenario adds `discussion` → `command:/bin/true`.
  Test env slots hold sentinel values only; existence is checked, values
  never enter a report.
- Observed identity evidence per bound role: login (= bound actor),
  host instance (= endpoint), repository stable id, observation time.
- Egress allowlist: `crates.io`, `static.crates.io`.
- Paths: `TAISAN_CONFIG` → temp `config.toml`; `TAISAN_STATE_DIR` →
  temp state root (flag → env → XDG precedence); workspace root defaults
  to `<state>/workspaces`; store probe reads `<state>/store.db`.
- Probe: an injected scripted `ProbePort` (library tests) or, on the
  CLI, `ProbeMode::Unavailable` — no adapter backend is wired in this
  runtime, so `check --probe` fails closed at stage 8 with
  `capability.unknown`, an empty operation log, and zero writes.

## Design notes

- **Stage order is the fail-closed spine.** Stages run 1→8; the first
  failure stops the sequence and every later stage is reported
  `not_run` — never skipped silently, never executed. The report always
  lists all eight stages in `STAGE_ORDER`.
- **Observed identity, not declarations.** `identity_evidence` is
  written by `init` from explicit observed pointers (login, host
  instance, repository stable id per bound role) and refreshed only by a
  *passing* `check --probe`; stage 2 refuses success without it, so a
  config that never carried an observed identity read can never be
  reported successful.
- **The probe port has no write method.** `workloop_core::ports::
  ProbePort` exposes `read_actor_identity` and `read_capabilities`
  only; the report's `remote_writes` field is structurally pinned to 0,
  and a plain `check` never receives a probe backend at all.
- **No durable grant.** `check` opens no store, writes no config (plain
  run), creates no directories, and persists no success stamp — the
  report is per-run, and the next run re-derives every stage from live
  local state (hence the revocation test failing at credential
  resolution).
- **Bounded children.** Every child `check` starts (`command:` slot
  existence, observed `--version`) is bounded at 5 s; a wedged binary
  is killed and reported, never allowed to hang the preflight.
- **Store is read by header only.** Stage 7 reads the SQLite header
  (magic, page count, `user_version`) and never opens the database —
  opening can journal, WAL-flip, or migrate, which would violate
  read-only preflight.

## Non-claims

- No live host API was contacted; no credential value was resolved or
  echoed (existence checks only: env presence, file metadata, provider
  exit status).
- No adapter probe backend exists in this runtime: CLI `check --probe`
  fails closed at stage 8 by design; the read-only probe contract is
  exercised through the injected scripted port.
- No bubblewrap/namespace/egress enforcement is claimed — stage 6 only
  verifies primitive presence (U4/live scope).
- Fixture results support contract claims only; live claims require
  separately authorized live evidence.
