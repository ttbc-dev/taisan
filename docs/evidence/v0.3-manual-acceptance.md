## Claims boundary

Every row below carries exactly one label:

- **owner-run live evidence** — a real installation, a real conforming
  Worker implementing `taisan.worker.declaration/1` +
  `taisan.worker.request/2` + `taisan.worker.report/2` (for example the
  in-repo reference adapter `taisan-worker-claude` driving a real
  coding-agent runtime), the production in-process `github` host driver
  inside `taisan run`, real credentials by reference, and real host
  effects on **one** isolated repository under the recorded owner
  authorization. The commands may be run by the owner or an
  owner-designated operator named in that authorization.
- **automated fixture/contract evidence** — scripted adapters
  (`s1-bridge`), fixture sources or Workers (`workloop-fixture-worker`,
  `workloop-contract-worker`), temporary/in-memory stores, contract or
  unit tests. Citable only as supplemental context; a fixture or
  contract result **never** satisfies a row here.

Rules that bind this record:

- No scenario bridge or scripted coding/review shim substitutes for the
  real profile — a row produced through `s1-bridge`, a fixture Worker,
  or a test-harness path does not qualify.
- A row that did not run is `unexercised` with a reason — never `pass`
  by implication, never silently absent.
- An `unknown`, `failed`, or `uncertain` result stays exactly that —
  recorded, never coerced.
- The executing agent/operator can never approve this record; approval
  is the owner's separate act (§8).
- Credential **values** never appear — `env:`/`file:`/`command:`
  reference names only. A leaked value is an incident: stop, redact,
  rotate.
- No private *source* repository is named: counterpart systems appear
