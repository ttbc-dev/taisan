## Design notes

- The deadline gate sits in `admit_queued_role` — "the single seam every
  request creation passes" — so a queued Execution past the Work-wide
  automatic-time ceiling fails terminally instead of admitting a trial
  the same tick would then launch (phase 2 runs before the phase-5
  sweep). The terminal decision defers while host writes are
  outstanding, mirroring the existing budget gate and `lifecycle.md`
  (terminal release requires no outstanding writer/effect); the sweep's
  `queued` arm now applies the same guard through a shared helper.
- The supervision record is a derived view (`projection::supervision`):
  the earliest applicable deadline (Execution runtime deadline;
  Work-wide automatic-time deadline shifted by recorded human waiting),
  the held reservation keys, the held capacity slot, and the recorded
  writer's liveness. `stopped` is reported only for a supervisor-observed
  exit on record (or a writer proven unable to write); a failed or
  inconsistent record reports `unknown`.
- The `paused`-Execution exhaustion paths inside `fire_due_intent` were
  unchanged by this slice: the then-known unversioned-retirement /
  outstanding-effect gap there was tracked separately as a U5.1 shadow
  finding (#139) and is closed by `c8ed4bc`/`39957eb`, outside this slice.
