# U4.6c verification evidence — swap-window recovery: recollection and safe stop

Slice: U4.6c (`crates/workloop-exec/tests/swap_recovery.rs` — the
named restart-reconciliation, crash-recovery-table and recollection
scenarios under a changed `worker_argv`, the fail-closed U4.6 record
stamping they retain, and the two evidence-machinery checks;
`docs/worker-conformance-matrix.md` — the swap-window recovery section;
`docs/worker-protocol.md` — the swap-window recovery paragraph of the
U4.6 evidence record). The U4.6a/U4.6b machinery this slice relies on —
per-request adapter binding, effect-free `describe`, capability digest,
bound-argv re-verification, the durable handoff stages, and the
revision-stamped record format — was delivered earlier and is unchanged
here.

Claims boundary: every result below is a **fixture/contract** result
produced by local tests — real spawned reference-fixture and contract
Worker binaries under the POSIX supervisor, durable SQLite store
records, and real git workspace/handoff repositories. It supports
contract claims about this repository only. No live Worker runtime,
host, or E2E scenario was run; any live claim requires separately
authorized live evidence under the
[implementation start gate](../design-closure.md#implementation-start-gate).

## What the scenarios exercise

Three named scenarios in `swap_recovery.rs`, each retaining one
[U4.6 record](../worker-protocol.md#u46-evidence-record) to
`target/u4.6c-<scenario>.json` when the checkout yields a faithful
revision stamp:

1. **`u46c_restart_after_worker_argv_change_reconciles_in_flight_on_recorded_bindings`
   (WS-20, WS-03).** Two requests bind and launch real fixture
   `hang` writers under the prior selection; both Executions are
   mid-flight. The `worker_argv` then changes to the independent
   contract Worker and a fresh supervisor runs over the **reopened
   durable store**. The restart pass reconciles each in-flight
   Invocation — spawn count stays at 2 (no second writer), the stored
   `adapter_binding` (adapter ID, adapter version, runtime version,
   capability digest, argv) and the recorded writer identity are
   byte-identical across the restart (no migration), a fresh
   `describe` of the recorded argv re-verifies `Ready` against the
   stored binding, and a fresh `describe` of the *changed* argv
   selects a configuration repair against each stored binding
   (`adapter.identity_mismatch`, `capability.digest_mismatch`) — a
   repair for those requests, never a retarget. Only a request created
   after the change binds `workloop-contract-worker` (spawn count 3,
   a different capability digest). The follow-up safe stop cancels
   all three works: each execution reaches `cancelled` only after a
   durable stop intent covers its recorded identity and every identity
   in the intent inspects `Stopped`, with spawn count still 3 — the
   safe stop covers every recorded identity launched under the prior
   selection (and the new one) and never starts a writer.
2. **`u46c_interrupted_export_import_recovers_under_changed_config_without_duplicate_artifact_ids`
   (WS-11).** Two real fixture `clean-exit` writers finish under the
   prior selection in git workspaces carrying their produced branches;
   both Executions wait `HostWrite`. The `worker_argv` changes, the
   supervisor restarts with the handoff layout, and the sweep walks
   the crash-recovery table for the first artifact — one window per
   drive, each starting from the window's crash residue:

   | Window (crash-recovery table) | Residue the test creates | Recovery observed |
   | --- | --- | --- |
   | Before `export_started` | no export row, no ref | the sweep opens the row, exports, imports, and acknowledges; declared verification `Pass` on the produced commit |
   | After `export_started`, truncated bundle | row rewound to `export_started`, bundle overwritten with garbage | partial deleted (not evidence), re-exported, bundle verifies, acknowledged |
   | Bundle verified, import interrupted | row at `bundle_written`, leftover quarantine objects fetched, artifact ref absent | quarantine discarded, bundle re-imported, ref recreated under the expected-absent guard |
   | `imported` row, ref absent | row at `imported`, ref deleted | ref recreated after the stored manifest digest re-verifies |
   | Ref present, row still `imported` | row at `imported`, ref present | read-back matches, `acknowledged` committed |
   | Workspace lost before acknowledgement | second artifact's export row seeded, its workspace deleted | each sweep charges an attempt; the row settles `invalid(recovery_exhausted)` at exactly the configured bound of 3, never acknowledged, no ref minted |

   After **every** window the repository's
   `refs/taisan/artifacts/` set is asserted equal to exactly the one
   acknowledged ID, the store holds one row per invocation under its
   deterministic `<invocation>/<kind>` ID, re-drives change nothing
   (verification results stay at exactly 1), and the final full pass
   mints no duplicate artifact IDs. Spawn count stays at 2 throughout:
   recovery under the changed configuration never launches a worker.
3. **`u46c_recollection_acknowledges_and_retains_git_objects_under_changed_config`
   (WS-11, WS-01).** A real fixture `clean-exit` writer launched
   under the prior selection finishes in a git workspace; the
   Execution waits `HostWrite` — mid-Execution — when the
   `worker_argv` changes and the supervisor restarts. The restart
   pass recollects the artifact: the row reaches `acknowledged`, the
   ref resolves the produced commit, the declared verification
   (`git rev-parse HEAD`) records `Pass` bound to that exact commit,
   and spawn count stays at 1. The workspace `.git` and the managed
   `work/<work>` branch still resolve the produced commit, and the
   handoff repository holds the produced closure (`cat-file` plus a
   clean `fsck --connectivity-only`) — workspace and git objects
   survive the verified handoff. The request binding is unchanged
   across the restart and the recollection.

Two named checks guard the evidence machinery:

- `u46c_revision_stamp_is_fail_closed` — a stamp is either two full
  40-hex commit ids over a pristine checkout or no stamp at all; a
  dirty tree or an unanswerable git means *no record*, never a
  placeholder.
- `u46c_retained_record_carries_the_closed_field_set` — a retained
  record carries exactly the closed U4.6 field set
  (`schema_version`, `tested_revision`, `base_revision`,
  `claim_class`, `configuration_identity`, `command_scenario`,
  `result`, `evidence_refs`), the closed `fixture_supported` claim
  class, and every binding field (phase, adapter ID, adapter version,
  runtime version, capability digest, argv, request identity,
  invocation identity) on each adapter-selection entry.

Unlike the shared-suite helper, the stamp check here counts
untracked (non-ignored) files as dirt as well: this slice *adds*
files, so a commit that does not contain them can never stamp a
record.

## Configuration under test

The installation identity is the local test installation
(`host_instance = swap-recovery-host`, `repository =
swap-recovery-repo`, adapter `fixture`, contract version `1`). The
Worker selection under test is the configured `worker_argv`: the
reference-fixture binary (`workloop-fixture-worker`) before the
change, the independent deterministic contract Worker
(`workloop-contract-worker`) after it. Each selection reports through
the effect-free `describe` operation — adapter ID
`workloop-fixture-worker` / `workloop-contract-worker`, adapter
version `1.0.0`, runtime version `fixture-1.0.0` /
`contract-1.0.0`, and a capability digest over the declared
protocol/role/capability surface (fixture
`903619b2baf3427f681f7119da1644b2491a81a232948767360bcb8f88158f75`,
contract `d2b06e35a835558300085fbde20d3ce6bf4fd9c2643714ecd1b72d8a02f74848`).
Each request's first binding is stored on the durable
`InvocationRequest` and is immutable; recovery, stop proof, and
handoff read recorded identities, workspaces, and durable rows —
never the current `worker_argv`. The artifact-recovery bound under
test is the configured 3 attempts / 60 s.

## Non-claims

- No live Worker runtime, sandbox, host, or E2E scenario was
  exercised. These are fixture/contract results only.
- The produced commits in the recollection and crash-recovery
  workspaces are seeded by the test harness (as in the U4.4 handoff
  suite); the Worker processes are real spawned binaries, but no
  runtime-authored commit is claimed.
- No second production provider was added; the independent contract
  Worker remains a deterministic verification implementation bound only
  through `worker_argv`.
- No running-Invocation migration, resume capability, or outer-loop
  publication is claimed.
- The `tested_revision` stamp and the per-scenario record files are
  produced by the fail-closed machinery on the first run from a
  pristine checkout that contains this slice; this worker was
  instructed not to commit, so that run belongs to the landing of the
  slice, and no placeholder stands in for it here.
