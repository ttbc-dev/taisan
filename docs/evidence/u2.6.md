## Configuration under test

Eligibility is exercised against explicit per-category settings
(`CategorySettings` with `cas`), and against a real temporary state
root for the CLI smoke run. The closed documented defaults apply when a
category has no explicit setting. PlanBounds exercised: default
(`max_bodies: 256, max_bytes: 1 GiB`) and an explicit
`max_bodies: 2` bound.

## Non-claims

- No live host API, Worker runtime, or E2E scenario was contacted.
- No physical cleanup was run against a real installation; reclamation
  tests and the CLI smoke use temporary fixture directories.
- The external manifest-照合 review (opencode reviewer) was
  unavailable at delivery time (provider quota/billing error, exit 1);
  the code was self-reviewed locally instead. Dated in the PR body.
  The machine shadow review returned seven rounds of candidate findings.
  Round 1 (5 findings): 🔴 store-format upgrade refusal, 🟡 unvalidated
  public `reclaim_plan_entry`, 🟡 false `held`/`pinned` outcome on a
  lost present→reclaiming race, first-write-wins outcome recording —
  fixed in `98a4a00` with a regression test for the format upgrade;
  🔵 docs findings addressed by the `--apply` synonym and this record.
  Round 2 (4 findings): 🟡 the timed sweep's false `pinned` report on a
  lost race, and planned entries recorded `unavailable` for rows still
  `reclaiming` — both fixed in `4149a00` (state re-read replaces the
  false hold; `reclaiming` rows finish through the idempotent delete
  path); 🔵 schema.sql header updated to v4.
  Round 3 (4 findings): 🔴 public `reclaim_plan_entry` accepted
  `delete_error_limit = 0` — rejected as in the execute path; 🟡
  catalogue reclaim and the plan entry outcome are now one transaction
  (`finish_reclaim_and_record`), so a crash never strands a pending
  entry for a body this run already reclaimed; 🔍 the `cleanup
  --execute` result carries the phase-1 skipped list; 🟡 the report
  stats present bodies (bounded, resolved against the state root) and
  reports unstatable paths as `unknown` — covered by
  `report_counts_unstatable_bodies_as_unknown_not_present`.
  Round 4 (4 findings): 🟡 `retention cleanup` results (dry-run and
  `--execute`) now carry the pinned-but-otherwise-eligible bodies —
  "what pins prevented"; 🟡 phase-2 marks `present` entries through
  the eligibility-recomputing marking transaction
  (`mark_reclaiming_if_eligible`), so a `size_pressure` entry whose
  category fell back under the cap is held `within_limits`; 🔴 the
  pressure computation excludes unstatable bodies from `eligible_count`
  (previously only the bytes/caps were adjusted); 🔵 this record's
  review provenance is corrected.
  Round 5 (3 findings + 1 withheld): 🔴 `cleanup --execute` no longer
  overwrites the phase-2 `held` list with the phase-1 list (distinct
  `planned_held` / `planned_skipped` keys); 🟡 a row leaving `present`
  between the read and the marking transaction is re-read in place of
  aborting the pass with a store error; 🔴 size_pressure is authorized
  only on verified bytes (stat), with ghost bytes vetoed in plan
  collection, at the marking transaction and in report pressure —
  covered by `phantom_bytes_cannot_authorize_size_pressure`.
  Round 6 (3 findings): 🔴 resumed plans keep the phase-1
  skipped/held evidence (carried on the plan row, verified by
  `resumed_plan_keeps_the_phase_one_skipped_and_held_lists`);
  🟡 explicit cleanup takes the installation run lease
  (loser reports already_running) and the store layer re-checks each
  entry's outcome with bytes counted only by the transitioning
  process; 🟡 the format-4 migration gate requires the complete schema
  of the stamp being upgraded (v1 / v2 / v3 exemptions shrink
  accordingly); regression test
  `a_stamped_store_missing_an_earlier_additive_table_is_refused`.
  Round 7 (4 findings): 🟡 a lost insert-transaction race returns the
  other process's plan untouched (no mixed skipped evidence); 🟡 the
  report's pinned count and oldest age now come from the same
  stat-verified set as the byte accounting; 🟡 a v2 stamp may lack
  only the v3 additions (v2 tables are part of its own schema),
  covered by `a_stamp2_store_missing_v2_tables_is_refused`; 🔵 this
  record's provenance corrected.
- Per-category `max_bytes`/`max_age` are not configurable in this
  slice; the report applies the closed documented defaults from
  `docs/retention-policy.md`.
- The `--execute` flag name follows issue #112's acceptance criteria;
  `--apply` is accepted as a synonym (the retention policy's
  documented spelling). The policy document is unchanged pending owner
  confirmation of the canonical spelling.
