## Design notes

- The environment is *built*, never inherited: `PosixProcessControl`
  calls `Command::env_clear()` and applies exactly the `WorkerEnv`
  pairs the profile constructed. A variable not listed does not exist
  for the child — the boundary is an allowlist, not a denylist.
- `isolation_profile(id)` in `workloop-core` is the single resolution
  point shared by TOML validation (`Profile::validate_worker`), the
  `Installation::worker_isolation_profile()` accessor, and
  `build_supervisor` — a name refused at load can never be launched
  under.
- `isolation::prepare` runs for both the `describe` probe
  (`probe-<request_id>` scratch, plus `probe-prebind` in the run loop)
  and the launch (`inv-<invocation_id>` scratch). A preparation error
  on the launch path goes through `refuse_launch` — Invocation
  abandoned + `LaunchRefused` — the same path as a refused spawn.
- Scratch lives at `<workspace_root>/.isolation/`, a sibling of the
  `ws-*` workspaces, outside any git workspace so a worker's own
  `git add -A` cannot sweep it into an artifact. `sanitize_key`
  collapses `.` to `-` so `..` can never form a path component.
- This is the hygiene half of the permission boundary: same-UID
  filesystem reads outside the env boundary are the namespace machinery
  the U2.4/U4 slices own — required, not sufficient, per
  `docs/worker-protocol.md`.
