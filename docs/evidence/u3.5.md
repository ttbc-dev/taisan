# U3.5 verification evidence — unknown-effect reconciliation

Slice: U3.5 (Issue #106 — read-only reconciliation of outstanding
`pending`/`unknown` host-action intents against the remote's observed
post-state; reconcile-before-write presence checks so a lost receipt
can never be replayed into a duplicate effect; `unknown{actor_mismatch}`
for receipts authenticated by a non-bound actor whatever status they
claim; durable partial state across restart; reconciliation inputs
taken from the persisted intent, never from live configuration or a
rotated credential).

Claims boundary: every result below is a **fixture/contract** result
produced by local tests. It supports contract claims about this
repository only. No live host, Worker, or E2E scenario was run; any
live claim requires separately authorized live evidence under the
[implementation start gate](../design-closure.md#implementation-start-gate).

## Acceptance criteria mapping

| Criterion | Where exercised | Result |
| --- | --- | --- |
| Missing/`Unknown` receipts never trigger replay; reconciliation rereads host facts; a named test models a kill between apply and receipt-write | `reconciliation.rs::kill_between_apply_and_receipt_settles_from_the_host_read_not_a_replay` — the armed `crash_after_apply` kill switch drops the worker after the remote write and before the receipt persists; after a file-backed store reopen, the pre-write read adopts the landed push (no second push) and `reconcile_outbox` settles the open intent `applied` from the remote's own record; `applied()` stays at exactly two writes end to end | pass |
| Partial results survive restart; a persisted applied receipt beside a still-pending intent remains readable and reconciles | `partial_receipts_survive_restart_and_reconcile_after_reopen` — applied receipt and pending intent both readable after `SqliteStore::open` on the same database; reconciliation settles the pending intent from the reopened records | pass |
| A receipt authenticated by actor B for an intent bound to actor A records `Unknown{actor_mismatch}` and never settles | `receipt_by_another_actor_records_actor_mismatch_and_never_settles` — foreign-authenticated `applied` and `failed` claims both record `unknown{actor_mismatch}`; `effect_attributed_to_another_actor_never_settles_the_intent` — a remote-attributed foreign effect is recorded `actor_mismatch`, never adopted | pass |
| Credential rotation never rebinds outstanding intents | `credential_rotation_keeps_outstanding_intents_on_their_recorded_actor` — a rotated value authenticating as another actor is `credential_blocked` in both reconcile and apply; a same-actor renewal settles under the original binding | pass |
