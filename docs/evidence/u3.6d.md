### Failure-mode mapping notes

Every retained U3.6a–c scenario record maps to exactly one failure
mode; the record index below binds all 22 retained records (11 shared
scenarios × 2 implementations). Scenario-to-mode assignments beyond
the obvious name matches:

- `actor_replacement_cannot_retarget_outstanding_actions` →
  `permission_drift`: actor/credential/binding replacement is the
  drift of the authorization-and-binding axis the mode covers.
- `raced_write_read_back_reports_the_observed_post_state` →
  `partial_effects`: a racing actor's move between write and
  read-back is the partial/raced-effect observation the mode covers.
- `restart_and_config_change_reconcile_under_the_original_binding` →
  `lost_responses`: the outstanding open intent is a lost response
  reconciled from remote reads under the recorded binding.
- `partial_receipts_across_restart_reconcile_each_constituent_independently`
  → `partial_effects`: partial receipts across restart is the mode's
  namesake.
