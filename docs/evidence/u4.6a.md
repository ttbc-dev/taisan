## Evidence record format

The normative format is in
[worker protocol](../worker-protocol.md#u46-evidence-record). A record
contains `schema_version`, `tested_revision`, `base_revision`,
`claim_class` (`fixture_supported` or `live_evidenced`),
`configuration_identity` (installation config plus the adapter selection
active at request binding: adapter ID, adapter version, runtime version,
capability digest, argv/digest, request and invocation identities),
`command_scenario`, `result`, and `evidence_refs`. Fixture results are
labelled `fixture_supported`; only separately authorized live evidence
may be labelled `live_evidenced`. A patch/file digest supplements but
never replaces the tested branch revision.

## Configuration under test

The installation identity is the local test installation
(`host_instance = swap-host`, `repository = swap-repo`, adapter
`fixture`, contract version `1`). The Worker selection under test is the
configured `worker_argv`: the reference-fixture binary
(`workloop-fixture-worker`) and the independent deterministic contract
Worker (`workloop-contract-worker`). Each selection reports through the
effect-free `describe` operation:

- adapter ID: `workloop-fixture-worker` or `workloop-contract-worker`;
- adapter version `1.0.0`; runtime version `fixture-1.0.0` /
  `contract-1.0.0` (the fixture accepts an explicit
  `--runtime-version` used by WS-21);
- protocol versions, roles and capabilities hashed into
  `capability_digest`, together with the runtime product identity and
  the declared `resume`, `checkpoints`, `runtime_artifact_store` and
  `local_retries` surface.

The first binding is stored on the durable `InvocationRequest`
(`adapter_binding`) and is *the* stored declaration for that request —
immutable for the request's life. `Effect::BindRequestAdapter` updates
only an unbound request, so a later configuration edit cannot retarget
it. A running Invocation continues under the request's recorded argv
and identity. At launch the bound argv is probed again through the
supervisor's process-control port (own process group, bounded wait,
group signalled on timeout); a declaration that drifted under that argv
is a per-field mismatch — `adapter.identity_mismatch`,
`adapter.version_mismatch`, `runtime.version_mismatch`, or
`capability.digest_mismatch` — and a configuration repair that
authorizes no start. A refused request is terminal for its binding: it
is abandoned and re-issued under a new request, which binds the
declaration current at its first binding. `describe` itself is fail-closed:
a probe that does not answer with a declaration refuses the request as
`adapter.declaration_unavailable` and never compares or dispatches on a
synthetic declaration.
