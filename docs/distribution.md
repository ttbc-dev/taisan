# Binary distribution — cargo-dist pipeline

Status: **drafted wiring, no release exists** (issue #441). This page
describes the prebuilt-binary distribution route decided on #370:
cargo-dist builds release archives on GitHub Releases, publishes
Homebrew formulas to the owner's personal tap, and cargo-binstall
metadata lets `cargo binstall --git` fetch the same archives instead
of compiling. Nothing here publishes to crates.io, creates a tag, or
cuts a release — the first tag follows the
[release versioning](release-versioning.md) policy once #370 freezes
the candidate.

## What ships

The workspace allowlist in `[workspace.metadata.dist].packages`
distributes exactly the documented install surface
([v0.3 installation](v0.3-installation.md),
[reference adapters](reference-adapters.md)):

| Package | Installer binary | Homebrew formula |
| --- | --- | --- |
| `workloop-cli` | `taisan` | `taisan` |
| `workloop-tui` | `taisan-tui` | `taisan-tui` |
| `workloop-selector` | `public-issue-selector` | `public-issue-selector` |
| `taisan-worker-claude` | `taisan-worker-claude` | `taisan-worker-claude` |
| `workloop-fixture-worker` | `workloop-fixture-worker` | `workloop-fixture-worker` |

Every package builds for `x86_64-apple-darwin`,
`aarch64-apple-darwin`, `x86_64-unknown-linux-gnu`, and
`aarch64-unknown-linux-gnu`. There is no Windows or musl target: the
codebase is unix-only and containment is a Linux feature.

Excluded and why:

- `s1_bridge` and the legacy-named `workloop-cli`/`workloop-tui`
  binaries are built inside their packages but kept out of the
  release artifacts and installers
  (`[package.metadata.dist.binaries]`); they are scenario/dev tools,
  not the install surface. cargo-binstall requests every bin a
  package declares unless given `--bin`, and a declared bin missing
  from the archive fails the prebuilt fetch — so the documented
  binstall commands below pass `--bin` and place only the shipped
  binary on PATH. Omitting `--bin` makes binstall fall back to
  compiling the package from source, which builds and installs all
  of its bins.
- `workloop-fixture-selector`, `workloop-contract-worker`, and
  `taisan-executor` are test fixtures or unshipped surface. They are not
  in `packages` — which alone does not suffice: in cargo-dist 0.34.0 a
  versioned binary crate outside `packages` is still auto-detected and
  shipped (verified with `dist plan`), so each also carries
  `[package.metadata.dist] dist = false` in its own manifest to pin the
  exclusion through the #370 version freeze.

## Release flow

`.github/workflows/release.yml` is generated by `dist generate`
(cargo-dist 0.34.0, pinned via `cargo-dist-version`). Pushing a tag
matching `**[0-9]+.[0-9]+.[0-9]+*` — e.g. `v0.3.0` once the #370
version decision lands — runs: `plan` (`dist host --steps=create`,
which creates the GitHub Release on tag pushes) → per-target
`build-local-artifacts` matrix → `build-global-artifacts`
(installers, formulas, unified `sha256.sum`) → `host` (uploads the
artifacts and publishes the release) → `publish-homebrew-formula`
(commits each `Formula/<name>.rb` to `shimpeiws/homebrew-tap`) →
`announce`. Pull requests run `dist plan` only (`pr-run-mode =
"plan"`), which exercises the matrix without building.

`release.yml` is no longer fully generated. It carries a hand-applied
permissions patch, marked by a `LOCAL MODIFICATION` header: the
workflow-level `GITHUB_TOKEN` is scoped to `contents: read`, and the
two jobs that write to GitHub Releases escalate to `contents: write`.
`host` runs `dist host --steps=upload --steps=release` and
`gh release create`. `plan` runs `dist host --steps=create` on tag
pushes — the step that creates the release under `hosting = "github"`,
so it needs write too; on pull requests it runs only `dist plan`
(read-only), but GitHub job permissions cannot be conditional on the
event, so the tag-path write applies unconditionally. The remaining
jobs inherit read-only.

The same patch routes the tag name through `env:` vars. Tag names are
pushed refs and can contain `$(...)`/backticks, so `github.ref_name`,
`needs.plan.outputs.tag`, and `needs.plan.outputs.tag-flag` never
appear inside `run:` blocks as `${{ }}` interpolation — each step
reads them as shell variables (with `${TAG_FLAG:+$TAG_FLAG}` where the
flag is absent on pull_request runs). cargo-dist 0.34.0 cannot express
permissions for its built-in jobs
(`github-custom-job-permissions` covers only user-defined custom
jobs), so `[workspace.metadata.dist].allow-dirty = ["ci"]` keeps `dist
generate` from silently reverting the patch.

The cost of `allow-dirty`: `dist generate --mode=ci` (and `--check`)
skips `release.yml` entirely, so CI-affecting config changes no longer
regenerate it. To resync after editing `[workspace.metadata.dist]`,
temporarily remove `allow-dirty`, run `dist generate --mode=ci`,
re-apply the permissions patch (read at workflow level, write on
`plan` and `host`) and the env-var tag hardening, then restore
`allow-dirty`.

## Install routes

The binary routes exist once a release is published; until then the
[source route](v0.3-installation.md#1-build) is the only working one.

**Shell installer** — installs to `~/.cargo/bin` (`install-path =
"CARGO_HOME"`):

```sh
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/ttbc-dev/taisan/releases/latest/download/workloop-cli-installer.sh | sh
```

Substitute `workloop-tui`, `workloop-selector`,
`taisan-worker-claude`, or `workloop-fixture-worker` for the other
apps.

**Homebrew** — the formulas land in the owner's personal tap:

```sh
brew install shimpeiws/tap/taisan               # the CLI
brew install shimpeiws/tap/public-issue-selector
brew install shimpeiws/tap/taisan-worker-claude
brew install shimpeiws/tap/taisan-tui           # optional console
brew install shimpeiws/tap/workloop-fixture-worker
```

**cargo-binstall** — each disted package carries
`[package.metadata.binstall]` pointing at the same release archives,
so `--git` installs fetch prebuilt binaries. `workloop-cli` and
`workloop-tui` declare extra bins that are not in the archive, so
the command must select the shipped one with `--bin` (skipping
missing unrequested bins needs cargo-binstall ≥ 1.14.0); the other
packages declare a single bin and need no selection:

```sh
cargo binstall --git https://github.com/ttbc-dev/taisan workloop-cli --bin taisan
# for the console: workloop-tui --bin taisan-tui
```

## Owner-side prerequisites

These steps are owner operations, not part of this change:

- Create the tap repository `shimpeiws/homebrew-tap` on GitHub.
- Add a `HOMEBREW_TAP_TOKEN` secret to this repository — a token with
  write access to the tap (the generated publish job checks out the
  tap with it and commits the formulas as the workflow's configured
  git identity).
- Cut the first tag only after the #370 candidate/version decision;
  until then every package version is `0.0.0`, which is why each
  disted crate carries `dist = true` (cargo reports unversioned
  crates as `publish = false`, and dist would skip them). The freeze
  version bump makes artifacts report the real version.
- The `publish-homebrew-formula` job fails a release if the tap repo
  or token is missing; the GitHub Release itself is unaffected.

## Verification

`dist plan` (cargo-dist 0.34.0) produces five apps × four targets of
`*.tar.xz` archives, each with a `*.sha256` checksum plus a per-app
unified `sha256.sum`, a `*-installer.sh` shell installer, a Homebrew
`*.rb` formula, and a checksummed `source.tar.gz`. `dist build
--artifacts=global` emits the same installers and formulas under
`target/distrib/` for inspection without cutting a release.
